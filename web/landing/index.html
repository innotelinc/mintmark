What it tells you.

The appraisal is the whole product, so it says more than a price: it shows its reasoning and the parts it is unsure about.

◎Identification

Country, denomination, design, year, mint mark and visible variety — empty fields when a detail is not legible, rather than a guess.

◑Grade and condition

A Sheldon 1–70 grade with the adjectival name, judged on what the photograph actually shows.

＄Value range

Low and high in collector-market USD at that grade: roughly dealer-buy to fair retail, not a catalogue headline.

⚑Drivers and red flags

What makes up the value — key date, mintage, metal, demand — and visible cleaning, damage, corrosion or a cast fake.

⌕Next checks

Concrete things to look at or photograph next: reverse design, mint-mark position, edge, weight and diameter.

▣Your collection

Every appraisal is kept with its photo and thumbnail, under an anonymous id, so a collection survives a change of phone.

How an appraisal happens.

The photo never leaves the estate's own gateway, and the key that pays for the vision call stays on the server.

The photo is prepared

The app scales it to a 1280px long edge, encodes JPEG, and sends it with an optional note.

The server checks it

Image type and size, one appraisal in flight per visitor, and the daily allowance — so a refused request costs nothing.

The model answers in JSON

The gateway is asked for schema-constrained output, so the reply is an object rather than prose to parse.

The reply is clamped

Confidence 0–1, grade 1–70, low ≤ high, no value when unidentified — validated before anything is stored.

Where it runs.

One website, one iPhone app, one API — the same appraisal behind each.

About me.

I am Darnel Hunter, and I build the Innotel platform: identity, storage, billing, media, mail, the edge that fronts all of it — and the products on top. Mintmark is one of those products, and it is the smallest complete one: it has a real appraisal engine, a collection, a privacy page and a native app, with no account system to hide behind.

I write the software the way I would want an operator to inherit it: the standard spelled out in one place, the theme shared instead of reinvented per project, the deployment reproducible from a compose file, and the docs honest about what a check did and did not verify. This repository is an example of that — the same README shape, the same Unity theme and the same guards as every other project in the estate.

The rule I keep for Mintmark specifically: it must never flatter a coin. A worn common coin should come back worth cents, and the app should say what it cannot see.
